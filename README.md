## 项目简介

《克丽丝腾的实验室》是一款基于 **Qt Widgets + C++** 开发的二维重力反转解谜游戏。玩家不能直接控制主角小球左右移动，而是扮演实验室中的“重力调试员”，通过 `W`、`A`、`S`、`D` 改变空间重力方向，引导小球利用重力、墙体、机关和特殊模块穿过障碍，最终到达终点。

项目采用 JSON 文件组织关卡数据，包含主菜单、关卡选择、核心游戏场景、关卡编辑器、自定义关卡、进度存档和背景音乐播放等功能，形成了较完整的游戏功能闭环。

---

## 项目特性

- 基于 Qt Widgets 的桌面端图形界面；
- 使用 `QGraphicsScene` / `QGraphicsView` 实现游戏场景；
- 使用 `QTimer` 驱动游戏刷新与物理状态更新；
- JSON 驱动关卡系统，支持内置关卡与自定义关卡；
- 内置可视化关卡编辑器，可创建、校验、保存和试玩关卡；
- 支持通关进度、星级、死亡次数、最佳时间等记录；
- 支持背景音乐播放；
- 支持墙体、起点、终点、死亡区、钥匙、门、数据碎片、传送门、激光门、缓冲区和多方向蹦床等地图元素。

## 运行环境

建议使用以下环境：

- Qt 5 或 Qt 6；
- CMake 3.16 或以上；

推荐环境：

本项目主要在 Windows + Qt Creator 环境下开发与测试。

## 构建与运行

### 使用 Qt Creator

1. 打开 Qt Creator；
2. 选择 `kristenLab/CMakeLists.txt`；
3. 配置合适的 Qt Kit；
4. 先点击构建项目，生成 `build` 文件夹；
5. 将 `kristenLab/music/` 文件夹复制到 Qt Creator 生成的 `build` 目录或可执行文件所在目录；
6. 回到 Qt Creator，重新构建并运行项目。

项目使用外部 `music/` 文件夹播放背景音乐，因此需要确保该文件夹位于程序运行目录下。若未复制该文件夹，游戏仍可运行，但背景音乐可能无法正常播放。

### 背景音乐文件说明

本项目包含背景音乐功能，音乐资源位于：

```text
kristenLab/music/
```

由于背景音乐文件没有直接编译进 Qt 资源系统中，因此首次运行前需要手动将 `music/` 文件夹复制到构建目录中。推荐操作步骤如下：

1. 先在 Qt Creator 中正常构建一次项目；
2. 构建完成后，进入生成的 `build` 文件夹；
3. 将 `kristenLab/music/` 文件夹复制到 `build` 文件夹中；
4. 回到 Qt Creator，重新构建并运行项目。

完成以上步骤后，游戏启动时即可正常播放背景音乐。

如果运行时没有听到背景音乐，请检查：

- `build` 目录下是否存在 `music/` 文件夹；
- `music/` 文件夹中的音频文件是否完整；
- 程序运行目录是否为 Qt Creator 当前使用的构建目录；
- 系统音量或应用音量是否被静音。

### 使用命令行

在仓库根目录下执行：

```bash
cd kristenLab
mkdir build
cd build
cmake ..
cmake --build .
```

如果使用命令行构建，也需要将 `kristenLab/music/` 文件夹复制到生成的构建目录或可执行文件所在目录中。

程序运行时会读取可执行文件附近的：

```text
levels/
custom_levels/
music/
save/
```

因此请确保这些目录能够被正确放置到运行目录中。项目中的 CMake 配置已经包含 `levels/` 和 `custom_levels/` 的复制逻辑，`music/` 文件夹需要手动复制。

## 游戏玩法

玩家控制一个小球在地图中移动。游戏的核心机制是 **重力方向切换**。玩家需要利用不同方向的重力、地形和机关，使小球避开危险区域并到达终点。

游戏中会统计：

- 当前关卡；
- 游戏时间；
- 当前重力方向；
- 重力反转次数；
- 死亡次数；
- 通关状态。

部分关卡还会根据表现给出星级评价。

---

## 操作方式

| 按键 | 功能 |
|---|---|
| `W` | 切换重力向上 |
| `A` | 切换重力向左 |
| `S` | 切换重力向下 |
| `D` | 切换重力向右 |

玩家需要根据地图情况切换重力方向，让小球沿正确路线移动。

| 字符 | 含义 |

| `0` | 空地 |
| `1` | 墙体 |
| `2` | 起点 |
| `3` | 终点 |
| `4` | 死亡区 |

| `6` | 缓冲区 |
| `7` | 传送带，旧版保留 |
| `8` | 数据碎片 |
| `L` | 激光门 |
| `9` | 蹦床，方向为右上 |
| `u` | 蹦床，方向为左上 |
| `v` | 蹦床，方向为右下 |
| `w` | 蹦床，方向为左下 |
| `r` | 蹦床，方向为右 |
| `l` | 蹦床，方向为左 |
| `K` | 钥匙 |
| `A` | 门 |
| `B` | 传送门 |

## 关卡 JSON 格式

关卡文件保存在 `levels/` 或 `custom_levels/` 目录中，格式如下：

```json
{
  "name": "基础关",
  "targetReverseCount": 6,
  "map": [
    "111111111111",
    "120000000001",
    "100000000001",
    "100400000031",
    "111111111111"
  ],
  "editablePoints": []
}
```

字段说明：

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | string | 关卡名称 |
| `targetReverseCount` | number | 推荐或目标重力反转次数 |
| `map` | string[] | 地图数据，每个字符代表一个格子 |
| `editablePoints` | array | 玩家可编辑候选点 |

`editablePoints` 支持对象形式：

```json
{ "row": 3, "col": 5 }
```

也支持数组形式：

```json
[5, 3]
```

其中数组形式的顺序是 `[col, row]`。

## 自定义关卡

自定义关卡存放在：

```text
custom_levels/
```

游戏启动时会自动扫描该目录，并加载合法的 JSON 关卡文件。

自定义关卡不会受到内置关卡解锁进度限制，通常可以直接游玩。

## 关卡校验规则

加载或保存关卡时，系统会进行基本校验，包括：

- 地图不能为空；
- 每一行地图宽度必须一致；
- 必须有且只有一个起点 `2`；
- 至少需要一个终点 `3`；
- 门 `A` 需要搭配钥匙 `K`；
- 传送门 `B` 需要成对出现；
- 地图中不能出现未知字符；
- 玩家可编辑点不能放在墙体、起点、终点、死亡区、钥匙、门、传送门等关键格子上。

如果关卡不符合规则，将无法正常加载或保存。

## 关卡编辑器

项目内置了关卡编辑器，可以通过主菜单进入。

编辑器支持：

- 创建新关卡；
- 设置关卡名称；
- 设置地图宽度和高度；
- 设置目标反转次数；
- 表格化编辑地图；
- 选择不同地图块工具；
- 自动生成边框墙；
- 清空地图；
- 撤销与重做；
- 导入 JSON 关卡；
- 校验地图合法性；
- 试玩当前关卡；
- 保存到内置关卡目录或自定义关卡目录；
- 设置玩家可编辑候选点。

编辑器可以直接将当前关卡传入游戏场景进行试玩，不一定需要先保存文件。

## 进度存档

玩家进度保存在：

```text
save/progress.json
```

存档中会记录：

- 关卡是否通关；
- 最佳星级；
- 最短通关时间；
- 最少重力反转次数；
- 最少死亡次数；
- 最后通关时间；
- 当前最高解锁内置关卡。

内置关卡通常按照顺序逐步解锁，自定义关卡默认不受解锁限制。

说明：`save/progress.json` 是运行时进度文件。若该文件不存在，程序运行后会根据逻辑重新生成或更新存档。

图片和动画资源位于：

```text

```

Qt 资源文件为：

```text
resources.qrc
```

游戏运行时通过 Qt 资源系统访问图片，例如：


```text
music/
```

音乐文件作为外部资源读取，需要放在程序运行目录下。

## 核心模块说明

### MainWindow

`MainWindow` 是主界面控制模块，负责主菜单、游戏界面、关卡选择、帮助说明、关卡编辑器入口、状态栏显示、键盘输入提示和背景音乐启动。它主要负责界面切换和 UI 状态更新，不直接处理复杂的游戏物理逻辑。

### GameScene

`GameScene` 是游戏最核心的模块，负责地图加载、地图绘制、小球创建、物理移动、重力方向控制、碰撞检测、道具触发、机关判断、胜利与失败逻辑、游戏状态更新和临时关卡试玩。

游戏通过定时器周期性刷新场景，并根据当前地图格子和玩家输入更新小球状态。

### LevelManager

`LevelManager` 负责关卡数据管理，包括加载内置关卡、加载自定义关卡、保存关卡 JSON、校验关卡合法性和管理关卡来源路径。

### LevelEditorDialog

`LevelEditorDialog` 是独立的关卡设计器，负责可视化编辑地图，并支持保存、导入、校验和试玩。

### ProgressManager

`ProgressManager` 负责玩家进度存档，包括通关状态、星级、最佳记录和解锁关卡。

### AudioPlayer

`AudioPlayer` 是音频播放封装模块，底层使用 `miniaudio`，用于播放背景音乐和管理音量。
